# 딕테이션 채점·분석

먼저 `guide/listening.md`를 읽는다 (소리 패턴 치트시트·커리큘럼 기준 문서).

## 입력

- **원문 스크립트** + **사용자의 받아쓰기** 두 가지가 필요하다. 하나만 오면 나머지를 요청한다.
- 원문 없이 "이 자료 들었는데 채점해줘"라고 하면: 오디오를 들을 수 없으므로 스크립트를 붙여넣어 달라고 한다.

## 절차

1. **문장 단위 대조표** — 원문 / 받아쓰기를 문장별로 나란히 놓고 차이를 표시한다. 맞은 문장은 칭찬 없이 간단히 ✓ 처리, 틀린 부분만 자세히.
2. **오류 분류** — 각 오류를 두 축으로 분류한다:
   - **소리 문제** (못 들음): `guide/listening.md`의 치트시트 패턴(sinalefa, 약화된 d/g/b, 기능어 뭉침, b=v/h묵음, distinción)으로 태깅하고, 왜 그렇게 들렸는지 한국어로 설명.
   - **어휘 문제** (모르는 단어라서 못 씀): 몰랐던 단어 목록으로 분리.
3. **패턴 요약** — 이번 딕테이션에서 가장 많이 걸린 패턴 1~2개를 뽑고, 다음에 들을 때 집중할 포인트를 한 줄로 제시.
4. **어휘 연계** — 2번에서 나온 몰랐던 단어에 대해 "단어장에 추가할까?"라고 묻고, 추가하면 `/vocab-add` 절차로 처리한다 (새 단어 → `단어장.json`).
5. **진급 판단** — 사용자가 물으면 `guide/listening.md`의 Phase 진급 기준과 대조해 의견을 준다.

## 규칙

- 철자 실수(악센트 부호 누락 등)와 청해 실수를 구분한다 — 악센트만 틀린 건 "들었지만 표기 실수"로 가볍게 처리.
- 설명은 한국어로, 핵심 원리 + 예시 위주로 담백하게 (tutor.md 톤과 동일).
